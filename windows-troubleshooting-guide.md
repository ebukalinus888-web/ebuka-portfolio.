# Windows Troubleshooting Guide
**Project type:** Practice portfolio project  
**Role demonstrated:** IT Support / Help Desk

## Goal
Provide a repeatable first-response process for common Windows user problems.

## Workflow
1. **Clarify the issue:** Ask what changed, when it started, the exact error message, and who or what is affected.
2. **Check the basics:** Confirm power, cables/Wi-Fi, restart status, available storage, and whether the issue affects one app or the whole device.
3. **Connectivity:** Check Wi-Fi/Ethernet status and test a known website. If appropriate, run `ipconfig /all`, `ipconfig /flushdns`, and `ping` to a known address or gateway.
4. **Application issue:** Close and reopen the app, check for updates, verify sign-in, and record any error message before making changes.
5. **Performance issue:** Check Task Manager for unusually high CPU, memory, or disk use; review free disk space and pending updates.
6. **Validate:** Ask the user to repeat the task that originally failed.
7. **Document:** Record symptoms, checks performed, outcome, and any remaining impact.
8. **Escalate:** Escalate when there is a security concern, suspected hardware failure, widespread outage, privileged access requirement, or no progress after approved checks.

## Example ticket note
“User reported that a browser-based application would not load. Confirmed the device was connected to Wi-Fi and tested another website. Recorded the error message and checked whether the issue affected another browser. Next step: compare with service status and escalate with timestamps and findings if still unavailable.”

## Success criteria
- The user understands what was checked.
- Troubleshooting steps are documented.
- The original task is retested.
- Unresolved issues are routed to the correct team.

**Note:** This is a general practice guide. Follow the employer’s security policy and approved support procedures.
